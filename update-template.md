# Update template

Copy this template for each meaningful project update. Use an absolute date and timezone; distinguish the observation time from the publication time. Do not create an entry just because a scheduled check ran.

## YYYY-MM-DD — A concrete change

**Status:** proposed / prepared / submitted / live / verified / corrected

**What changed:** One or two sentences describing an action that actually happened.

**Evidence:** Link directly to the public result or primary source. For a changing metric, include the observation timestamp and platform. A saved draft is not a submitted application.

**What we learned:** State the observation first. Label any explanation of why it happened as a hypothesis unless the evidence establishes causality.

**Open questions:** What remains unverified or could change the conclusion?

**Next experiment:** One bounded action and the evidence that would justify continuing or changing it. Participation must not require a token purchase.

**Correction history:** Preserve a short explanation when correcting a material claim. Never silently replace an unsuccessful experiment with a success story.

## Publication checklist

- Include only project information intended for public release.
- Exclude credentials, wallet balances, private correspondence, local paths, browser-session details, and internal account-operation instructions.
- Check the chain and full contract address in every new destination link.
- Describe token locks and burns separately; omit unverified totals or dates.
- Disclose AI assistance and keep the independent-parody description clear.
- Do not imply a16z, Arc, Circle, CoinGecko, or another organization endorses this project.
- Report real work and uncertainty without return promises or manufactured urgency.
